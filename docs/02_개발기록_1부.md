## 1. 문제 정의

음성만으로 한국어 감정 7종을 분류하고, 상담·비즈니스에 쓸 수 있는 형태로 서비스화.
텍스트는 쓰지 않는다 — 같은 문장도 말투에 따라 감정이 다르기 때문.

> **9/21 갱신** — 서비스의 주인공을 분류기에서 **감정 흐름 탐색**으로 옮겼다. §11~12 참조.

## 2. EDA에서 발견한 세 가지 함정

**(1) CSV의 `상황` 컬럼은 정답이 아니다**
성우에게 준 **연기 지시**였고, 평가자 5명의 청취 다수결과 **68.1%만 일치**.
- disgust로 연기한 것의 48%만 혐오로 들림, 16%는 분노로
- surprise로 연기한 것의 38%는 그냥 중립으로 들림
→ 라벨을 **5명 다수결(hard) + 투표분포(soft)** 로 재정의. `발화문`·`감정세기`는 manifest에서 제외.

**(2) 화자가 111명뿐이고 상위 2명이 22%**
speaker_id가 없어 `(소스, 나이, 성별)` 조합으로 화자 추정. 랜덤 split이면 모델이 목소리를 외운다.
→ **화자 독립 분할** 강제, split.py에 누수 assert 추가.

**(3) 클래스 불균형 13.6:1** (sadness 16,856 vs surprise 1,241)
→ 지표를 accuracy가 아닌 **UAR(macro recall)** 로. CB-Focal + 균형 샘플러.
→ 추가 발견: happy·surprise는 5차년도_2차에만 존재 (소스=라벨 누수 위험).

## 5. 막혔던 지점과 해결

**버그 1 — LayerDrop으로 학습이 매 스텝 깨짐**
WavLM은 학습 모드에서 레이어를 확률적으로 건너뛰어 `output_hidden_states` 개수가 스텝마다 달라진다 → `RuntimeError: stack expects a non-empty TensorList`. eval 모드에선 재현 안 됨.
→ `config.layerdrop = 0.0` + 더미 forward로 개수 실측. **합성 데이터로 전 구간을 돌려보다 발견.**

**버그 2 — 평가 리포트 크래시**: test에 없는 클래스 → `classification_report(labels=...)` 명시.
**버그 3 — 전처리 행 중복**: merge로 되붙이다 120→146. map 기반 매핑으로 교체.
**버그 4 — pandas `.style` 충돌**: `style` 컬럼명이 Styler를 반환. `style_tag`로 변경.
**버그 5 — 대용량 전송 스크립트가 9분 낭비**: sftp `reput`은 원격 파일이 있어야 동작. ssh `stat`으로 크기 먼저 재고 put/reput 선택 + 정체 가드.
**버그 6 — cmd가 ssh 인자의 따옴표를 깨뜨림**: 원격 스크립트를 `.sh`로 분리해 `ssh host "bash -s" < script.sh`.

**판단 착오 1 — 특징 추출 모델 선택**: `emotion2vec_plus_large`는 이미 자체 9클래스 분류기까지 파인튜닝된 모델이라 전이 불가(0.287). SSL 원본으로 교체 시 0.573.
→ 진단은 **선형 프로브**로 "특징이 나쁜가 헤드가 나쁜가"를 분리.

**판단 착오 2 — 손실 설정의 이중 보정**: 프리즈 모델에서 CB-Focal + 균형 샘플러를 함께 쓰자 희소 클래스로 흩뿌림(surprise 정밀도 0.003).

**재현성**: 동일 설정 재실행에서 UAR 0.069 차이(프리즈 방식). WavLM은 0.7342→0.7341로 결정적.

**환경**: transformers 5.x ↔ torch 2.4.1 비호환으로 보였으나 진짜 원인은 **CPU 빌드 torch**. `--torch-backend=auto`로 해결.

## 7. 온디바이스 경량화 (9/18)

| 항목 | 값 |
|---|---|
| 파라미터 | 9,497만 |
| fp32 | 약 380MB |
| **int8 동적 양자화** | **197MB** |
| RTF | 0.057 (3.7초 → 0.21초) |

`quantize_dynamic`을 모든 Linear에 적용하자 `TypeError: expected Tensor ... but got method`. WavLM 어텐션이 `q_proj.bias`를 속성으로 직접 읽는데 양자화 Linear는 bias가 메서드가 된다.
→ 이름에 `.attention.`이 없는 Linear만 양자화(73개 중 25개).

## 8. SKT 감정 음성 코퍼스 (9/17~)

- large: 화자 8명 × 약 19,000발화 ≈ 15만, 감정 16종, 48kHz, 67.3GB
- small: 화자 약 500명, 라벨 없음

**한계 3가지**: 화자 8명뿐 / 청취 검증 없음 / 16종 중 46%가 7감정에 매핑 불가.

**결정적 발견** — 화자 M0001에서 `NEUTRAL` 라벨 수와 `#지문`(나레이션) 발화 수가 **각각 4,797로 정확히 일치**. SKT의 중립은 대화 중립이 아니라 나레이션 낭독.

## 9. 대화 흐름 실측 — `wav_id`가 ObjectId였다 (9/21) ★

`wav_id` 24자리는 MongoDB ObjectId이고 앞 8자리에 **녹음 시각**이 들어 있다.
- 43,991건 전부 유효 · 2020-01-20 ~ 11-25
- 같은 프로세스 + 화자 + 5분 이내 → **세션 9,400개**
- 세션 내 연속 동일 시나리오 → **시나리오 블록 24,851개**

**실측** (3발화 이상 블록 1,687개 · 발화 7,601건 · 연속 쌍 5,914개)

| 발견 | 수치 |
|---|---|
| 감정 관성 | 다음도 같은 감정일 확률 **84.6%** (셔플 기대값 46.3% → 1.8배) |
| 전이 비대칭 | 분노→슬픔 **21.1%** vs 슬픔→분노 **4.7%** (4.5배) |
| 감정은 흘러간다 | 1번째 발화 일치율 88.3% → 7번째 **66.0%** |

감정별 배수: 혐오 28.4× · 공포 14.1× · 중립 10.5× · 분노 3.3× · 슬픔 1.5×

**이 수치가 말하지 않는 것**: 한 시나리오 발화가 전부 같은 화자라 감정 전염은 못 잼 · 발화 간격 중앙값 44초 · 모델 성능이 아니라 사람 5명이 들은 결과.
