## 1. 문제 정의 — 왜 이걸 만들었나 (슬라이드 3~4)

### 논리 구조
장면 3개 → 공통점 1개 → 못 잡는 이유 3개 → 그래서 만든 것 3단계

**장면 3개** (통계는 장면을 뒷받침하는 용도. 장면부터 말하고 숫자는 뒤에)

| 장면 | 대사 | 숫자 |
|---|---|---|
| 집 · 저녁 식탁 | "괜찮아. 신경 쓰지 마." | 결혼생활 만족도 남편 80.5 / 아내 70.7 → **9.8%p 차이** |
| 상담센터 · 통화 3분 | "네… 알겠습니다." | 직장 내 괴롭힘 **신고** 5년 새 2,130 → 12,253건 (**5.8배**) |
| 안부 전화 | "별일 없어." | 국민 **21.1%**가 외로움, **16.2%**는 "아무도 나를 잘 알지 못한다" |

> ⚠️ **괴롭힘 숫자는 '신고 접수 건수'이지 발생 건수가 아니다.** 말할 때도 "신고가"라고 정확히. 각주에도 박아뒀다.

**공통점**: 신호는 그 자리에서 지나가고, 남는 건 결과뿐.

**왜 못 잡나 (3)**

1. **말은 남고 말투는 사라진다** — 녹취록에는 "괜찮아요"만 적힌다. 감정은 톤·속도·떨림에 실려 있는데 그게 안 남는다.
2. **대화 중에는 안 보인다** — 듣고 답하느라 바쁘다. "그때 좀 이상하긴 했지"는 항상 사후에 나오는 말.
3. **녹음이 있어도 안 듣는다** — 3분을 처음부터 다시 듣는 사람은 없다. **어디를 들어야 할지 모르니까.**

**그래서 만든 것**: 3초마다 읽는다 → 흐름을 그린다 → 그 구간만 듣는다 (10초면 확인)

### 왜 그렇게 했나
문제를 "감정을 분류한다"가 아니라 **"어디를 들어야 할지 알려준다"**로 정의했다. 이 정의 덕분에 뒤의 모든 선택(3초 창, 임계값 보류, 구간 재생, 운영 액션 단위 출력)이 하나로 이어진다.

## 2. 왜 음성인가 / 왜 파형인가 (슬라이드 5, 18)

- 같은 "괜찮아요"도 톤·속도·떨림이 다르면 뜻이 다르다.
- **텍스트 감정분석(STT)은 말투를 버리고 통화 전문을 만든다** — 정확도 문제 이전에 **프라이버시 문제**다. 우리는 내용을 저장하지 않는다.
- 입력 후보 3가지 중 우리가 고른 것:

| 입력 | 모델이 보는 것 | 문제 |
|---|---|---|
| 텍스트(STT 변환) | 말의 내용 | 말투가 사라지고 전문이 남는다 |
| MFCC·스펙트로그램 | 사람이 설계한 특징 | 설계에서 빠진 정보는 못 쓴다 |
| **원시 파형 16kHz (우리)** | 높낮이·세기·속도·음색 전부 | 사전학습 모델이 특징을 스스로 찾는다 |

> **용어 정리**: 우리 데이터는 **비정형 데이터(음성 파형)**다. CSV에 있던 발화문 텍스트·'상황' 컬럼 같은 **정형 컬럼은 manifest 단계에서 전부 제외**했다. 학습 입력은 16kHz 파형 하나.

## 3. 데이터 — 왜 이 데이터이고, 라벨을 왜 다시 만들었나 (슬라이드 7~8)

### AI-Hub 「감정 분류를 위한 대화 음성」

- 4차년도 · 5차년도 · 5차년도_2차 / **43,991클립 · 약 45시간 · 48kHz mono**
- 고른 이유 3가지: ① 낭독이 아니라 **대화 녹음** ② 큰 모델을 다시 가르칠 만큼 **양이 충분** ③ 라벨이 **사람이 느낀 감정**(평가자 5명 투표)

### ★ 이 프로젝트에서 제일 중요한 발견 — 68.1%
데이터에 원래 붙어 있던 '상황' 컬럼은 **성우에게 준 연기 지시**였다. 그런데 평가자 5명이 실제로 느낀 감정과 비교하니 **68.1%만 일치**했다.

- **혐오 연기의 48%만 혐오로 들렸다** (16%는 분노로)
- **놀람 연기의 38%는 그냥 중립으로 들렸다**
- 분노 연기의 25%는 슬픔으로

→ **조치**: '상황' 컬럼 폐기. 5명 투표의 **다수결 = hard 라벨**, **투표 비율 = soft 라벨**로 정답을 다시 만들었다.

> **왜 중요한가**: 우리가 이 데이터를 골랐기 때문에 이걸 찾을 수 있었다. 정답이 하나뿐인 데이터였다면 **라벨이 틀렸다는 사실조차 몰랐을 것**이다. 질문 들어오면 이 문장으로 답하면 된다.

## 4. EDA — 진단 (슬라이드 10~12)

EDA는 **데이터를 건드리지 않고 보기만 한 단계**, 전처리는 **실제로 바꾼 단계**. 질문 들어오면 이 한 줄로 구분한다.

| # | 발견 | 숫자 | 조치 |
|---|---|---|---|
| ① | 연기 지시 ≠ 사람이 느낀 감정 | **68.1%** 일치 | 라벨 재정의 (다수결 + soft) |
| ② | 클래스 불균형 | 슬픔 16,856 vs 놀람 1,241 = **13.6:1** | 주지표 UAR · 균형 샘플러 · CB-Focal |
| ③ | 소스·음량 편차 | happy·surprise가 특정 차수에만 | 16kHz 리샘플 · 피크 정규화 · 무음 트림 |
| ④ | 화자 편중 | 111그룹 중 **상위 2명이 22%** | **화자 단위 분할** (목소리 암기 차단) |

## 5. 전처리와 분할 — 숫자를 셀 수 있게 (슬라이드 14~16)

```
43,991 (원본)
 → 39,188  라벨 필터: 동점·전원 불일치 4,803개 제외
 → 39,180  오디오 처리: 0.8초 미만 등 8개 제외
 → train 31,162 (79명) / val 3,178 (16명) / test 4,840 (16명)
```

- **버린 4,811개는 전부 이유를 셀 수 있다.** 이게 포인트다.
- 전처리: 48kHz → **16kHz** 리샘플, **피크 정규화**, 앞뒤 무음 제거(30dB), 16kHz 캐시 1회 생성 후 모든 실험이 공유
- 학습 때와 똑같은 정규화를 **서비스에서도** 쓴다: `(y − 평균) / max|y| × 0.891`
- 길이: 평균 4.9초 · 중앙값 4.3초 · **8초 상한**(88.6%가 들어옴, 긴 건 잘라 사용)
- **분할은 사람 단위.** 같은 목소리는 train/val/test 중 한 곳에만.

### 왜 그렇게 했나
랜덤으로 나누면 같은 사람 목소리가 시험에도 들어가서 **점수가 부풀어 오른다**. 실제로 이걸 나중에 한 번 직접 겪었다(§8 누수 사건).

## 6. 모델 — 무엇을 어떻게 학습시켰나 (슬라이드 19)

### 구조
```
16kHz 파형 (최대 8초)
 → CNN 인코더 (동결 · 20ms 단위)
 → 트랜스포머 12층 (WavLM-base+ 사전학습)
 → 13개 층 출력의 가중합  ← 가중치도 학습된다
 → Attentive Statistics Pooling (감정 실린 구간에 가중)
 → 헤드 256 → 7감정 확률
```

- 총 **9,497만 파라미터**, 통째로 파인튜닝(백본 포함)
- 학습: batch 32 · 10 epoch · **CB-Focal + soft KL** · bf16 · RTX 4090

### 용어를 이렇게 설명하면 된다

- **레이어 가중합**: 12층 중 어느 층 정보를 쓸지 모델이 직접 정하게 한 것. 실제로 **상위층(L09~L11)에 몰렸다** → 감정은 음소가 아니라 상위 표현에 실려 있다는 뜻.
- **Attentive Statistics Pooling**: 3초 안에서도 감정이 실린 구간에 더 가중치를 줘서 평균낸다.
- **soft KL**: 5명 투표 비율 자체를 정답의 일부로 학습 → "사람도 헷갈린 샘플"을 헷갈린다고 배운다.
- **CB-Focal**: 개수 적은 감정, 헷갈리는 샘플의 오답에 더 큰 벌점.

## 7. 지표 — 여기서 틀리면 발표 전체가 흔들린다 ★

| 지표 | 뜻 | 왜 쓰나 |
|---|---|---|
| **UAR (주지표)** | 감정별 재현율의 **평균** | 개수 적은 감정도 **똑같이 한 표**. 슬픔만 찍는 모델을 걸러낸다 |
| WAR (정확도) | 전체 맞힌 비율 | 다수 감정이 많으면 부풀려진다 |
| macro F1 | 정밀도·재현율 균형 | 보조 |
| 랜덤 기준 | 7클래스 = **0.143** | 0.287이 "랜덤의 2배"라는 감각을 준다 |

### ★★ 시험지가 2개다 — 절대 섞어 말하면 안 된다
| 시험지 | 크기 | 무엇 |
|---|---|---|
| **고신뢰 test** | n=3,329 | 평가자 4명 이상 동의한 '쉬운' 샘플만 |
| **전체 test** | n=4,840 | 애매한 샘플까지 전부 |

- 이 각주를 **먼저 말하면 점수를 딴다**: "시험지가 다른 두 줄은 비교하지 않습니다."

## 8. 실험 6개 — 그리고 왜 1등을 안 골랐나 (슬라이드 20)

| 모델 | 방식 | test UAR | 판정 |
|---|---|---|---|
| emotion2vec+ large | 특징 고정 | 0.287 | 기각 |
| emotion2vec base | 특징 고정 | 0.573 | 기각 |
| **WavLM-base+ · 고신뢰 2.5만** | 전체 파인튜닝 | **0.734** | **기준 모델** |
| WavLM × emotion2vec 앙상블 | 확률 가중평균 | **0.745 (1등)** | **기각** |
| WavLM · 전체 4.4만 | 전체 파인튜닝 | 0.675* | 다음 단계 |
| **+ SKT 4만 + 로짓 보정** | 이어학습 + τ0.6 | **0.695*** | **서빙 모델** |

### 이 장의 핵심 3개

1. **"제일 센 모델"이 제일 좋은 특징은 아니었다** — emotion2vec+ large는 이미 자체 9클래스 분류기까지 파인튜닝된 모델이라 임베딩이 전이되지 않았다(0.287, 제로샷 0.326보다도 낮음). SSL 원본으로 바꾸자 0.573, **2배**.
   - 진단 방법: **선형 프로브**로 "특징이 나쁜가, 헤드가 나쁜가"를 분리해서 확인했다.
2. **점수 1등(앙상블 0.745)을 버렸다** — 내부 +0.011인데 **외부 검증에서는 이득 0**. 복잡도를 감수할 근거가 없어서 단일 모델로 서빙.
3. **재현성** — 프리즈 방식은 같은 설정 재실행에서 UAR이 0.069나 흔들렸다(0.5729 → 0.6418). 파인튜닝(WavLM)은 0.7342 → 0.7341로 결정적.

## 10. 실패에서 배운 것 (슬라이드 24) — 포폴에서 제일 값나가는 부분

### CASE 1 · 데이터 누수 (점수가 너무 잘 나왔다)

- 증상: 이어학습 모델이 test에서 **0.7145** — 기준(0.675)보다 높음
- 의심하고 추적: test 화자 16명 중 **11명이 학습 화자**, 4,840개 중 **1,494개가 이미 학습한 파일**
- 원인: `min_votes`가 달라지면 화자 정렬 순서가 바뀌어 **split 자체가 달라진다**
- 교훈: **체크포인트는 split과 한 쌍이다**

### CASE 2 · 숨은 변수 (데이터를 뺐더니 더 나빠졌다)

- SKT의 NEUTRAL이 실은 **나레이션 낭독**이라는 걸 발견(화자 M0001에서 NEUTRAL 수와 '#지문' 발화 수가 **각각 4,797로 정확히 일치**)
- 그래서 "SKT 중립을 빼면 중립 정밀도가 오를 것"이라는 가설 → **실험으로 기각**
- 중립이 13,902 → 4,769로 줄자 **역빈도 샘플러가 남은 중립을 3배 더 자주 뽑아** 중립을 남발 (정밀도 0.573 → **0.462**)
- 교훈: **데이터 비율을 바꾸면 샘플링도 같이 바뀐다**

### CASE 3 · 좋아 보이는 지표 (내부 점수만 올랐다)

- 앙상블 내부 +0.011, 중립 제거 시 UAR +0.049 — 둘 다 매력적
- 그러나 외부 검증 이득 0, 중립 제거는 **에스컬레이션 오탐 증가**
- 교훈: **서비스 지표까지 확인하고 결정한다**

## 11. SKT 혼합과 로짓 보정 — 재학습 없이 +0.03 (슬라이드 22~23)

### 혼합
151,680 → 매핑 가능 119,411(78.7%) → 전처리 115,062 → **4만 발화 균형 추출** → AI-Hub train 31,162 + SKT 40,000 = **71,162**

- 불균형 **16.5:1 → 약 9:1**
- SKT는 화자가 8명뿐이라 **시험에는 쓰지 않았다.** 판정은 AI-Hub test로만.

### 결과가 이상했다
mix40k: UAR 0.6754 → **0.6626 (−0.013)**. 데이터를 늘렸는데 주지표가 내려갔다.
그런데 감정별로 보니 **정밀도는 크게 올랐다** (놀람 .602→**.810**, 공포 .723→**.816**). 모델이 "확실할 때만 희소 감정을 고르는" 쪽으로 이동한 것.

### 로짓 보정 (logit adjustment)
확률을 학습 데이터의 감정 비율^τ 로 나눠 **다수 감정 쏠림을 편다.**
```
보정 logits = logits − τ · log(학습 분포)
```

- **τ는 val에서만 고르고 test에는 한 번만 적용** (test로 고르면 반칙)
- 결과: mix40k + τ0.6 → **UAR 0.6945 · WAR 0.7211**
- 기존 모델도 보정하면 UAR은 비슷(0.6967)하지만 **WAR이 0.667로 무너진다**. mix40k는 0.721을 지켰다.
- 해석: **SKT가 만든 판별력 이득이 쏠림에 가려져 있다가 보정으로 드러났다.** 재학습 0분.

## 12. 중립은 감정인가 (심화 질문 대비)

"중립을 빼고 6감정 + 보류로 가면 좋아지나?"를 저장된 확률만으로 검증했다.

| 채점 조건 | UAR | ACC |
|---|---|---|
| 지금 7감정 | 0.6945 | 0.7211 |
| 중립 라벨 제외·중립 예측은 오답 (공평) | 0.7041 | 0.7384 |
| 중립 선택지 자체 제거 | 0.7533 | 0.7968 |

- 공평 비교에서 **+0.010뿐**. 0.7533은 시험이 쉬워진 효과이지 개선이 아니다.
- 사람 라벨도 같은 말을 한다: 중립 샘플은 n_votes 3.27(타 감정 4.08), entropy 0.754(0.403)
- 보류 방식 비교: 중립=보류(커버 80.7% / 정확도 75.8%) vs **신뢰도 0.70 보류(커버 50.3% / 정확도 90.1%)** → 신뢰도 방식이 압도적
- **결론: 중립 클래스는 유지. 판단 보류는 신뢰도 임계값으로만.** UI 표기는 "중립"이 아니라 "뚜렷한 감정 신호 없음".

## 13. 외부 검증 — 학습에 없던 목소리 (슬라이드 25)

AI 합성 음성으로 감정별 발화를 만들어 시험했다(표본 약 10개 구간, test 셋과 별개).

| 채점 단위 | 정확도 |
|---|---|
| 7감정 그대로 | **50%** |
| 운영 액션 4묶음 (에스컬레이션/케어/관찰/정상) | **90%** |
| 긍정·부정 2분류 | **100%** |

- 세부 감정은 틀려도 **좋고 나쁨의 방향은 한 번도 틀리지 않았다.**
- 더 중요한 발견: **WavLM과 emotion2vec이 같은 구간에서 같은 실수(중립→기쁨)를 했다.** 서로 다른 두 모델이 같이 틀렸다면 모델 결함이 아니라 **두 데이터가 '중립'을 다르게 정의**한 것.
- → 그래서 **서비스 출력을 7감정이 아니라 운영 액션 단위로 설계**했다. 이 장은 "정확도 50%"가 아니라 **"설계 근거를 얻었다"**는 장이다.

## 14. 범용성 — 모델 하나, 규칙표만 바꾼다 (슬라이드 26)

모델이 **항상 내보내는 값**: 7감정 확률 + 긍부정(valence −1~+1) + 각성도(arousal 0~1) + 신뢰도

| 현장 | 같은 출력을 이렇게 읽는다 |
|---|---|
| 상담센터 (구현) | 분노·혐오 → 에스컬레이션 / 슬픔·공포 → 케어 |
| 교육 | 부정 + 낮은 각성이 이어지면 → 학습 이탈 신호 |
| 헬스케어·돌봄 | 슬픔 비율의 주간 추이 → 정서 변화 알림 |
| AI 에이전트 | 긍부정·각성도 → 응답 말투 조절 |
| AI 음성 품질평가 | 의도한 감정과 일치율 → 합성 음성 채점 |

**모델을 다시 학습하지 않는다. 매핑 표와 임계값만 바꾼다.** 7감정 라벨에 묶이지 않도록 연속 좌표(V/A)를 함께 내보내는 이유가 이것이다.
> 현재 구현된 매핑은 상담센터 1종, 나머지 넷은 확장 예시라고 정직하게 말한다.

## 15. 아키텍쳐 — 시연 직전에 30초 (슬라이드 27)

### 컨테이너 3개 (`docker compose up` 한 번에 기동)
| 컨테이너 | 역할 |
|---|---|
| **web (nginx)** | 화면 정적 서빙 + `/api` 프록시 |
| **api (FastAPI)** | 업로드 접수 · 조회 · 통계 · 서명 URL 발급 |
| **worker** | 같은 이미지, 실행 명령만 다름 — 실제 추론 담당 |

### 요청 흐름 ①~⑦

1. 브라우저에서 녹취 업로드 (현장·지역 선택, 100MB 제한)
2. api가 원본을 **Storage에 저장**하고 DB `analyses`에 **status=queued**로 등록 → **즉시 id 반환** (기다리게 하지 않는다)
3. worker가 **2초마다 큐를 보고** 한 건 집어감
4. 16kHz 변환 → **3초 창 / 1.5초 간격** 슬라이딩 → WavLM 추론 (CPU)
5. 현장·지역 규칙 + **임계값 0.70** 적용 → `segments`에 구간 결과 저장, `analyses`를 done으로
6. 화면이 상태를 조회해 타임라인·대시보드 렌더 (결과 2초 · 대시보드 10초 주기)
7. 구간 클릭 → **서명 URL**로 그 지점부터 재생 (버킷은 비공개)

### Supabase

- **PostgreSQL 3테이블**: `analyses`(통화) · `segments`(3초 구간) · `feedback`(오분류 신고)
- **Storage**: 원본 녹취(비공개 버킷) · 모델 best.pt
- **접근 통제**: **RLS 전면 차단** + 서버 전용 secret 키 (브라우저로 절대 안 나간다)

### 정직하게 말할 것

- 로그인 화면과 실시간 push(Realtime)는 **아직 없다.** 지금은 서버 전용 키로만 붙고, 화면이 주기적으로 조회하는 방식. **다음 단계다.**

### 실측

- **69초 통화 → 45구간 · 추론 36.8초 · 전체 54.6초 (CPU, RTF ≈ 0.53)**
- worker 컨테이너만 늘리면 처리량 증가 (`--scale worker=N`)
- 온디바이스 경량화: 파라미터 9,497만 / fp32 380MB → **int8 197MB** / RTF 0.057(GPU 기준 측정)
  - 양자화 중 어텐션이 깨져서(`q_proj.bias`를 속성으로 직접 읽음) **이름에 `.attention.`이 없는 Linear만** 양자화 (73개 중 25개)

### 순서와 각 화면의 의미

**① 대시보드 먼저 (시스템 상태 줄)**
화면 맨 위 5칸이 5초마다 갱신된다. **"지금 이게 실시간입니다"**가 이 줄의 전부다.

| 칸 | 보이는 것 | 무엇을 증명하나 |
|---|---|---|
| api 컨테이너 | FastAPI 정상 · 가동 시간 | 이 응답이 온 것 자체가 증거 |
| worker 컨테이너 | 대기 중 / 분석 중 · **심박 N초 전** · 처리 건수 | 워커가 **따로 살아서** 큐를 보고 있다 |

| Supabase | 연결 지연 ms · 3테이블 | DB가 실제로 붙어 있다 |
| 작업 큐 | 대기 / 분석 중 / 완료 / 실패 | 비동기 큐가 돈다 |

> 💡 **가장 세게 먹히는 연출**: worker 칸이 "대기 중"인 걸 보여준 뒤 파일을 올리면, 그 칸이 **"분석 중"으로 바뀐다.** 백엔드가 진짜로 도는 증거로는 이게 제일 강하다.

**② 새 분석 — 현장과 지역을 고른다**

- 현장(상담센터/교육/돌봄)을 바꾸면 **해석 규칙과 임계값**이 바뀐다. **모델은 그대로다.** ← §14와 이어지는 지점
- 지역을 고르면 지역 보정 계수가 적용된다. **보정 계수는 아직 실측값이 아니라 설계값**이라고 정직하게 말한다.

**③ 분석 중 화면**

- 5단계가 순서대로: 오디오 변환 → 3초 창 분할 → WavLM 추론 → 지역 보정·판단 보류 → 현장 규칙 적용
- 상태가 **"대기 중(워커가 곧 집어갑니다)" → "WavLM 추론 중 · N초 경과"**로 바뀐다 = 큐가 도는 증거
- 끝나면 게이지가 100%까지 차고 **"완료 · N초 · M개 구간 분석"** 실제 값이 뜬 뒤 넘어간다
- 여기서 할 말: **"지금 업로드 응답은 즉시 돌아왔고, 무거운 추론은 워커가 뒤에서 하고 있습니다."**

**④ 결과 화면 — 감정 흐름**

- 가로축은 시간, 선은 긍부정(valence). 아래 띠가 3초 구간별 감정.
- **비어 있는 구간 = 판단 보류** (신뢰도 0.70 미만). **"모를 때는 모른다고 합니다."** ← 이 서비스의 정체성
- 그래프의 꺾인 지점을 클릭 → **그 지점부터 재생**된다. **"3분을 다 듣지 않고 10초면 확인됩니다."** ← 문제 정의(§1)의 3번째 이유에 정확히 대응
- 오분류 신고 버튼 → DB에 쌓이고 **신고 30건마다 재학습**(§17)

**⑤ 다시 대시보드**

- 방금 올린 건이 **집계에 반영**돼 있다 (완료 건수·구간 수 증가)
- 확인이 필요한 건 = 위험 구간이 길거나 판단 보류가 많은 순

4. 원본은 서버 밖으로 내보내지 않는다

> 예상 질문 **"AI가 다 한 거 아닌가요?"** → "가설·지표·채택 기준은 저희가 정했고, **AI가 낸 결론도 세 번 기각했습니다.** 검증 루프가 있어서 틀린 제안이 걸러졌습니다."
