## 1. SKT 혼합 학습 실행과 결과 (9/22)

서버에 코드·AI-Hub 캐시·체크포인트 전송, uv 가상환경(torch 2.14+cu130).
`run_train.sh`: nohup + GPU 지정 + smoke 모드. smoke 50배치 통과 시 배치당 0.309s · VRAM 12.8GB · 10ep 약 1.9시간 예측.

### 버그 7 — split 기준이 다르면 체크포인트를 바꿔 끼울 수 없다 (누수 발견)

이어학습 출발점을 `pilot_1006`(고신뢰 split)으로 잡고 full split test로 채점했더니 **UAR 0.7145**. 기존 full_1731(0.675)보다 높아 의심하고 추적:

- full test 화자 16명 중 **11명이 pilot의 train 화자**
- test 4,840개 중 **1,494개가 pilot이 학습한 바로 그 파일**
- 원인: `split.py`가 화자 크기 기준으로 pool을 섞는데 `min_votes`가 달라지면 화자 구성·순서가 달라져 split 자체가 바뀐다

→ 출발점을 full_1731로 교체. 서버 재현 기준선 **UAR 0.6754 / WAR 0.7145**(PC 값과 일치).
→ **체크포인트는 split과 한 쌍이다.**

### 버그 8 — merge의 균형 추출이 O(n²)

`balanced_take`가 한 개 뽑을 때마다 `sum(len(p) for p in picked)`로 전체를 다시 셌다(4만 개 → 수십 분). → `len(picked)`로 교체, 수 초로 단축.

### SKT 준비 실측

- `skt_manifest.py --map extended --label-conf 0.7` → 151,680 중 **119,411 사용**(78.7%), 깨진 라벨 10,792건 자동 복원
- 전처리 115,062개 성공 · 4,349개 제외(0.8초 미만) · 총 126.6시간
- split(화자 지정): train 57,556 · val 29,045 · test 28,461
- merge `--add-max 40000` → mix train **71,162** (AI-Hub 31,162 + SKT 40,000)
  - 추가분: 중립 9,133 · 분노 7,456 · 슬픔 7,143 · 공포 6,649 · 기쁨 6,600 · 놀람 2,700 · 혐오 319
  - 불균형 16.5:1 → 약 9:1

### 결과 — mix40k (test n=4,840)

| | full_1731 | mix40k | 차이 |
|---|---|---|---|
| **UAR (주지표)** | 0.6754 | 0.6626 | **−0.013** |
| WAR | 0.7145 | 0.7302 | +0.016 |
| macro F1 | 0.6857 | 0.6985 | +0.013 |

- 재현율: 슬픔 .789→.841 · 기쁨 .502→.612 · 중립 .688→.640 · **놀람 .663→.520**
- 정밀도: 놀람 .602→**.810** · 공포 .723→**.816** · 중립 .514→.573
- 해석: "확실할 때만 희소 감정을 고르는" 쪽으로 이동. 애매하면 슬픔으로 흡수
- **놀람을 2,700개 추가했는데 재현율이 오히려 하락** → 스튜디오 연기 놀람과 대화 놀람의 도메인 차이
- val 곡선: ep0 0.5537로 떨어졌다 ep5 0.6190 회복(출발점 0.6174) → 망각 후 회복, ep8 early stop

## 2. 로짓 보정 — 재학습 없이 UAR +0.03

확률을 학습 분포^τ로 나눠 쏠림을 편다. **τ는 val에서만 고르고 test에는 한 번만 적용.**

| | τ | test UAR | test WAR |
|---|---|---|---|
| full_1731 | 0 | 0.6754 | 0.7145 |
| full_1731 + 보정 | 0.8 | 0.6967 | **0.6671** |
| mix40k | 0 | 0.6626 | 0.7302 |
| **mix40k + 보정** | **0.6** | **0.6945** | **0.7211** |

보정 후 UAR은 동급(차이 0.002)인데 **WAR이 갈렸다.** 기존 모델은 보정 시 슬픔 재현율이 .79→.64로 무너지지만 SKT 혼합 모델은 0.721을 지킨다.
→ **서빙 후보 = mix40k + τ0.6.** 산출물 `src/logit_adjust.py`

## 3. 중립(neutral) 구조 분석 — 재학습 없이 (9/23)

| 채점 조건 | UAR | ACC | n |
|---|---|---|---|
| 지금 7감정 | 0.6945 | 0.7211 | 4,840 |
| 중립 라벨 제외·중립 예측은 오답 (공평) | 0.7041 | 0.7384 | 4,010 |
| 중립 선택지 자체 제거 | 0.7533 | 0.7968 | 4,010 |

- 공평 비교에서 **+0.010뿐**. 0.7533은 시험이 쉬워진 효과
- 보류 비교: 중립=보류(커버 80.7% / 정확도 75.8%) vs **신뢰도 0.70 보류(커버 50.3% / 정확도 90.1%)**
- 중립 예측 933개 중 **773개(83%)가 저신뢰** → 중립은 대체로 '모르겠다'의 다른 이름
- 사람 라벨: 중립은 n_votes 3.27(타 감정 4.08) · entropy 0.754(0.403) → **사람도 중립에서 덜 합의**
- 서비스 지표: 7감정 에스컬레이션 F1 0.7925 vs 6감정 0.7780 → 중립 제거 시 오탐 증가로 손해

**결정**: 중립 유지 · 보류는 신뢰도로만 · UI 표기는 "뚜렷한 감정 신호 없음" · 리포트에 포함/제외 UAR 병기

## 4. mixa 결과 — 가설 기각 (9/23)

SKT 중립(나레이션) 9,133개를 빼면 중립 정밀도가 오를 것이라는 가설은 **틀렸다.**

| | mix40k | **mixa** |
|---|---|---|
| test UAR | 0.6626 | **0.6432** |
| 중립 정밀도 | 0.573 | **0.462** ↓ |
| 중립 재현율 | 0.640 | **0.796** ↑ |
| 기쁨 → 중립 오답 | 20.8% | **44.4%** |

**원인 — 균형 샘플러와의 상호작용**: train 중립이 13,902 → 4,769로 줄자 역빈도 샘플러가 남은 중립을 약 3배 더 자주 뽑아 중립을 남발. 오염원이라 의심한 SKT 나레이션 중립이 오히려 **'다양한 중립 소리'의 평형추**였다.

→ **데이터 비율을 건드릴 때는 샘플러와 함께 봐야 한다.** 단일 변수만 바꿨다고 생각했지만 샘플링 빈도까지 같이 바뀌었다.

## 5. 기획발표 피드백 반영 (9/22)

| 피드백 | 반영 |
|---|---|
| 감정별 음성을 들려줄 것 | "들어보기" 장 신설 — 5/5 일치 클립 7개 + "혐오 연기 → 분노로 들린" 대비 클립 |
| 날짜별 수집→전처리→불균형 시각화 | "데이터가 늘어난 순서" 2레인, "전처리 결과" 깔때기 |
| 전처리 과정 시각화 | 실제 클립 1개로 4단계 + 전/후 재생 |
| 무엇을 학습시켰는지 명확히 | 입력→정답→모델→학습→시험 한 장 요약 |
| EDA 강조 | 7×7 히트맵 + 분포 3종 |
| 간트·아키텍처에 대시보드 | 간트차트, 아키텍처에 대시보드 블록 + Stats API 흐름 |
| 사투리 데이터 | AI-Hub 방언에 **목소리 기준 감정 라벨 없음** → 지역별 오탐 평가용으로 |

덱 17장 → 31장. 장마다 전용 애니메이션.
버그: 공통 등장 효과와 전용 효과가 겹쳐 **나타났다 사라졌다 다시 나타나는 현상** → 전용 효과가 걸린 요소는 공통 효과를 건너뛰도록 수정.

## 6. 운영 메모 — GPU 1 학습 중단

발열을 이유로 GPU 1에서 돌렸더니 메모리 18GB를 잡은 채 **8분간 step 0, P8(18W)로 멈춤**. GPU 1에 Xorg·gnome-shell(화면)이 함께 물려 있었다.
→ **학습은 GPU 0 고정.** `run_train.sh`를 `GPU=${GPU:-0}` · `CFG=${CFG:-configs/mix.yaml}`로 바꾸고, 시작 직후 `pgrep -af src/train.py`로 실제 적용된 config를 확인하는 절차 추가.
